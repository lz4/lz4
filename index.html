LZ4

Star

LZ4 is a lossless compression algorithm, providing compression speed > 500 MB/s per core (>0.15 Bytes/cycle). It features an extremely fast decoder, with speed in multiple GB/s per core (~1 Byte/cycle). A high compression derivative, called LZ4_HC, is available, trading customizable CPU time for compression ratio. LZ4 library is provided as open source software using a BSD license.

Command line pipelines

These benchmarks measure the command lines themselves, on the same system, in pipelines where a link of limited speed, a storage device or a network, separates stages running at the same time.

  • Reading static content
    from storage
  • Transferring dynamic content
    over the network

Reading static content

Static content, such as an OS kernel or video game assets, is compressed once, then read from storage, and decompressed while it is read.

Each bar measures, for instance for lz4 -9 :

lz4 -9 -c silesia.tar > f.lz4
LINK < f.lz4 | lz4 -d -c > /dev/null

where LINK limits the speed of the storage device (see bench-pipeline.sh).

Transferring dynamic content

Dynamic content, such as network packets, RPCs or database replication, is compressed, sent over the network, and decompressed, the three at the same time.

Default settings, or a single compression thread. A single thread : lz4 -T1, zstd -T1, pigz -p 1.

Each bar measures, for instance for lz4 -1 :

lz4 -1 -c < silesia.tar | LINK |
lz4 -d -c > /dev/null

where LINK limits the speed of the network (see bench-pipeline.sh).

Documentation

The LZ4 block compression format is detailed within lz4_Block_format.

For streaming arbitrarily large amount of data, or compress files of any size, a frame format has been established, detailed within the file lz4_Frame_format.

Custom LZ4 implementations

The following versions compress data blocks with the LZ4 compression algorithm in various programming languages. They use the block compression format, and deal with metadata (like compressed_size) in various custom ways (or none at all, letting the caller deal with it). Consequently, they are not interoperable with LZ4 command line utility, nor (generally) between themselves.
